UVmini 1240

Menu in Datalyse

Measure at one wavelength
Spectrum, wavelength scan
Baseline, wavelength scan
Zero value

The communication is special with many handshakes so the terminal program in Datalyse cannot be used. No support for add-ons such as plug in cards and multicell has been programmed into Datalyse.

UVmini must be in remote control otherwise Datalyse will be unable to communicate with the device. This means that measurements performed locally cannot be transferred to Datalyse!

However a baseline performed from UVmini will also be correct in remote control.

Baud rate 9600, uneven parity, 1 stop, 7 data bits. No version command. The cable is standard.

If the communication does not work, the reason might be that:

The device is busy, e.g. scanning.
The device is not in remote control, press F4 (PC Ctrl) on the display.

Turn off pc and device and start over.

UV1201

Menu in Datalyse:

Graphical measurement (t, f(t))
Absorbance, table measuring.
Setup spectrum parameters: wavelength, step values ...
Read spectrum, transfer a spectrum to the pc.
Kinetics.

Note that the device must have an expansion card for the serial communication to work. You can Datalyse with the spectrum card and the kinetics card. Note the names in the menu above.

There are several cards but you only need the spectrum card. The kinetics card can measure absorbance and transmittance as a function of time but this is also possible with the spectrum card.

Cable: (from meter to pc) 2-2, 3-3 and 7 - 5

on the pc end short circuit 4-6 and 7-8.

Ask about the price before ordering the cable!

The communication is unusual:

repeat
send #5
receive answer
until answer = #6
send command { e.g. "D" }
receive answer

In spite of this, it is possible to use the terminal program in Datalyse, since Datalyse automatically sends the repeat - until loop before the command.

Baud rate 9600, no parity, 1 stop, 7 data bits. No version command.

Read spectrum:

The data transfer only takes a moment. This is fortunate since you might have to transfer your data several times.

The reason is that you might not have gotten the number of measuring points per nm right. It depends on Scan Speed and Scanning Range:

    Scanning range  
    <= 200 nm <= 500 nm > 500 nm
Scan fast 0.2 nm 0.5 nm 1 nm
Speed medium 0.5 nm 0.5 nm 1 nm
  slow 1 nm 1 nm 1 nm

On the image above maximum - minimum = 600 which is more than 500, therefore one measuring per nm.

Shimadzu transfers the data in reversed order, f(lambda max) ... f(lambda min).

If the spectrum contains for instance 401 values and you have set Datalyse to transfer 601 values, you will get a spectrum beginning with 200 zeros.

Setup spectrum parameter:

The Shimadzu spectrophotometer has not any commands for reading wavelength settings, measuring method or scan speed. Instead it is possible to set the values from the pc. This way the values are known already.

If the communication does not work, the reason might be that:

The cable is wrong.
The device lacks an expansion card, inserted up front.
You have not selected any of the menu topics.
The device is busy, e.g. scanning.
Turn off pc and device and start over.

Shimadzu has been tested 14/11 1998 (and again 20/1 1999). Some smaller corrections have been made in Datalyse and a problem concerning table measuring has been corrected. In this case Shimadzu sends data + char(17). This must be an error that arose when modifying the software in Shimadzu. If you get the error message "Erroneous measuring", you should get an update of Datalyse.

Every device has advantages and disadvantages. Some are important for the programmer, some for the user as well. Shimadzu has the problem that a number of codes are missing. This makes it difficult for instance to transfer a spectrum correctly.
